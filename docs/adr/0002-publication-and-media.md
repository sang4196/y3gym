# ADR-0002 — 공개 반영과 미디어 보호 v0.2 초안

## DEV-05-B 주소 확인·지도 표시 (2026-10-05)

네이버 Maps 전용 현행 연결 약관(시행2025-03-20, 확인2026-10-05)에 따라 결과 좌표/주소/후보를 저장·재사용하지 않는 흐름을 이번 단위의 구현 기준으로 채택했다. 자체 기본주소와 운영자 확인 상태만 저장하고 기본주소 변경 시 같은 부모 트랜잭션에서 확인을 무효화한다. 상세주소만 변경하면 유지한다. 기존 Branch 권한·CSRF·edit_version·부모/사진 원자성을 유지한다.

공개 `location`은 항상 null이고 새 `map`은 확인된 공개 지점의 `{provider:'naver', query:현재 기본주소}` 또는 null이다. 관리자의 입력 주소 위치 확인과 방문자의 네이버지도 보기에서 공식 SDK로 각각 새 조회해 현재 Map/Marker에만 사용한다. 단일 유효 결과와 전체 주소의 보수적 일치를 요구하고, 기본 로고/저작권 유지·요청 전 외부 연결/이용 정보 안내·pagehide 정리/bfcache 새 조회를 적용했다. 운영자의 확인 의사이며 서버가 외부 조회 성공을 증명하는 기능은 아니다.

기본 설정은 비활성/공개 SDK 식별값 빈 값이다. 실제 키·API·브라우저·위치/쿼터·런칭 고지/동의와 상용 배포는 미검증이며 전체 Proposed 채택이 아니다. 아래 DEV-05-A의 현행 정책 미확인/좌표 준비 설명은 당시 이력이다. 근거와 검증은 [DEV-05-B 보고서](../verification/dev-05-b.md)를 따른다.

## DEV-01 한정 채택 기록 — 2026-10-05

사용자 실행 승인으로 SiteContent/Branch/BranchPhoto에 한정하여 P-01 현재값 저장 즉시 반영·부모/사진 원자성, P-02 최초0개/첫 공개본점/공개 본점1개/마지막비공개차단, P-03 일반 운영자 영구삭제/원본덮어쓰기금지·새자산교체, P-04 비공개원본/썸네일 보호·공개사용처기반 표시본을 구현 기준으로 채택했다. 일반 폼에서 새 본점 선택 또는 현재 본점 비공개+대체 본점 선택을 함께 저장한다. 다른 모델의 P 정책·운영 저장소/배포는 기존 Proposed를 유지한다.

구현은 PostgreSQL의 콘텐츠 단위 advisory transaction lock을 쓴다. 쓰기는 exclusive, 공개 DTO 다중 쿼리와 변환 완료까지 shared로 보호한다. 첫 공개에서 기존 행이 없어도 직렬화하며 본점 unique/check 제약과 잠금 내 존재 검사를 병행한다. 부모 폼의 edit_version으로 오래된 편집을 거부한다. 지점 폼의 본점 유일성 선검사는 원자적 교체를 막지 않도록 잠금 내 최종 검증으로 옮겼다. 사진은 부모 폼에서만 편집하며 타 부모 ID를 명시적으로 거부한다. raw SQL/임의 ORM bulk update를 안전한 편집 경로로 보장하지 않는다.

이미지 공개 조회는 Site/공개 Branch/BranchPhoto의 FK 기반 SQL EXISTS로 판정한다. Post 전체 리비전 O(n) 실험 스캔을 승격하지 않았다. 원본/내부 변환본은 인증과 컬렉션 권한 확인, 공개 표시본은 고정 변환과 매 요청 사용처 확인, 모두 no-store다. 로컬 파일 전달은 운영 프록시/스토리지 보호 검증을 대체하지 않는다. 정확한 RV 부분 결과·한계는 [DEV-01 보고서](../verification/dev-01.md)를 따른다. 아래 전체 RV/정책 상태 표는 최초 계획 이력이며 일괄 Accepted/PASS가 아니다.

## DEV-03 한정 채택 기록 — 2026-10-05

사용자의 순차 승인과 설계 지시에 따라 Post의 P-01 수정 초안/공개본 분리, P-03 새 자산 교체·영구 삭제/덮어쓰기 차단·과거 버전의 새 초안 복원, P-04 공개 사용처 기반 표시본/인증 미리보기를 구현 기준으로 채택했다. 제목/분류/본문/이미지는 live_revision에서 읽고 최초 공개시각은 유지, 공개 updated_at은 마지막 명시적 공개 시각이다. title/대표alt200자, 빈 초안 허용·공개 제목 및 텍스트 또는 본문 이미지 필수·모든 참조 파일/권한 재검증을 적용한다. P-02 및 기존 Site/Branch/Trainer 동작은 유지하며 Popup과 전체 정책을 일괄 Accepted로 바꾸지 않는다.

공개/철회 때 live_revision·시각·PostImageUse(post,revision,image)를 같은 PG 콘텐츠 exclusive lock/트랜잭션으로 변경한다. 이 인덱스는 파생 공개 이미지 집합이며 Revision이 원본이다. SQL EXISTS에 live 및 인덱스 revision=현재 live_revision을 확인하여 다른 버전의 인덱스가 초안 접근권한을 주지 않게 한다. Site/Branch/Trainer 공개 참조와 OR 결합하며 공개 DTO 생성·이미지 판정은 동일 shared lock을 사용한다. 모든 공개 Post를 파이썬에서 스캔하지 않는다. 필터는 공개 리비전 category, 정렬은 first_published_at DESC/PK DESC다.

설치 Wagtail7.4.3의 일반 편집/publish와 과거 버전 복원을 확인했다. generic 단건 철회는 모델 unpublish를 직접 호출하지 않으므로 제품 view에서 공통 처리로 연결하고 게시 권한·edit_version을 검사한다. 복원 화면의 Publish와 위조 요청을 막고 다시 열어 공개하게 한다. 기존 리비전 덮어쓰기 요청·자동저장·예약·일괄 Post 작업은 지원하지 않으며 서버에서도 차단한다. 직접/일괄 삭제와 파일 덮어쓰기는 기존 차단을 유지한다. raw SQL/임의 ORM bulk update·기본 action 클래스를 직접 호출하는 비공식 쓰기·수동 인덱스 조작은 지원 경로가 아니다. 별도 운영 관리 명령을 추가할 때에도 이 경계를 따라야 한다.

RV-01·08~12의 해당 서버 부분, 과거 버전 복원/파일 유실·공개 인덱스 실패 rollback·동시 공개/철회·양방향 조회 대기와 기존28개 회귀는 [DEV-03 보고서](../verification/dev-03.md)를 따른다. 실제 브라우저·팝업 시간 경계·운영 저장소/프록시·성능은 미검증이다.

## DEV-04 한정 채택 기록 — 2026-10-05

Q-01 사용자 결정(모든 팝업 Post 필수)과 순차 개발 설계 지시에 따라 Post당 최대1개 Popup, P-01 현재 설정 즉시 반영·PG 전체 저장/stale, P-03 영구삭제/파일덮어쓰기 금지·새자산 선택, P-04 현재 활성 팝업 사용처 이미지 판정을 이 단위의 기준으로 채택한다. Popup의 비활성 준비/활성필수/기간/길이 및 직접·일괄 삭제 방어를 적용하고 Post의 공개 상태·초안·시각은 변경하지 않는다. 일반 운영자에게 add/change/view_popup만 추가하며 계정은 저장하지 않는다.

후보는 shared 잠금 후 단일 now로 Post live/live_revision AND enabled AND starts<=now<ends, 정렬 priority ASC/starts DESC/PK ASC, linked title은 실제 공개 리비전이다. 이미지도 같은 조건의 SQL EXISTS이며 기존 Site/Branch/Trainer/Post 사용처와 공유·마지막 참조 정책을 유지한다. scheduler/장기 캐시 없이 매 표시본 요청의 서버시각으로 판정한다. 방문자 숨김은 이미지 권한이 아니다. Popup 설정 쓰기와 Post 공개/철회는 동일 exclusive 잠금이고 후보 DTO·이미지 변환은 shared로 완료한다.

홈 비모달 안내의 한 탭1회·KST ID별 오늘숨김·서버시각+monotonic 경과·오래된 응답 취소를 채택한다. 저장소 미지원 시 문서 내 메모리로 닫기/1회를 보완하지만 탐색을 넘는 기억은 보장하지 않는다. 실제 열린 화면의 원격회수·고객계정·추적/외부쿠키는 추가하지 않는다. raw SQL/임의 bulk update 등 공통 저장 경계를 우회하는 비공식 쓰기는 지원하지 않는다. [DEV-04 보고서](../verification/dev-04.md)의 서버/Node 부분 결과를 실제 브라우저·운영 보호 검증으로 확대하지 않으며 전체 P/ADR을 일괄 Accepted로 바꾸지 않는다.

## DEV-07-A 로컬 준비 한정 기록 — 2026-10-05

순차 승인 범위에서 WSGI/Gunicorn26.2.0을 **운영 후보의 로컬검증**에 한정 적용했다. product venv에 Gunicorn1개만 해시 고정 추가하고 기존37개 버전·local/test 설정은 유지한다. production 설정은 필수 호스트/HTTPS origin/키/PG·별도 비공개media/static/tmp를 명시하고 위험한 값은 시작거부한다. Django의 임의 forwarded 신뢰는 끄며 Gunicorn의 명시 peer만 허용, 제어소켓은 비활성이다. 실제TLS 전 HSTS0·includeSubDomains/preload false이고 check --deploy의 W004 경고1개를 그대로 기록한다.

실제 개발/SPIKE를 백업하지 않고 새 test role 전용 고유DB 두 개·합성미디어에 PG18.6 dump/restore와 manifest/참조·리비전·공개/초안/미디어 권한을 검증했다. 원본쓰기 중지·정확한 대상/owner/OID·빈대상·경로/symlink·체크섬·0600/0700·실패거부가 연습의 경계다. 연습 생성DB/시험프로세스만 정리하고 증거를 보존했다. 운영백업 암호화/보존/책임/외부보관/RPO·RTO·대상Linux/HTTPS·배포는 TBD/NOT_RUN이며 전체 ADR을 Accepted로 승격하지 않는다. [DEV-07-A 보고서](../verification/dev-07.md)와 [미적용 배포 후보](../deployment/linux-candidate.md)를 따른다.

## 1. 배경

지점·시설 사진과 트레이너·소속·약력은 함께 편집되지만 공개 버전의 단위가 불명확하면 미완성 내용이나 부분 변경이 노출될 수 있다. 최초 지점 준비와 운영 중 마지막 공개 지점의 비공개 전환도 구분해야 한다. 공개 API의 객체 필터링만으로 이미지 직접 URL을 보호할 수는 없다.

확정 범위는 고정 구조의 홍보 홈페이지, 가격 비공개, PT 연계 배제, 단일 소속 트레이너, 공통 게시글·기간제 팝업이다. C-01~05는 그 의미와 검증 전제를 명확히 한 보정이다. 아래 P-01~04는 **운영자/사용자 승인 대기**이며 이 작업이나 문서 저장이 승인은 아니다. CMS 채택은 [ADR-0001](0001-runtime-and-deployment.md)의 A-01 Proposed다.

## 2. 제안 — P-01~04 Proposed

### 2.1 P-01: Post만 공개본과 수정 초안 분리

목적은 소개 정보의 편집 비용을 줄이면서 게시글의 미공개 수정본 유출을 막는 것이다.

| 모델 | 공개 반영 정책과 단위 |
|---|---|
| SiteContent | 별도 수정 초안 없이 유효한 설정 저장 커밋 후 새 조회에 반영 |
| Branch + BranchPhoto | 지점 필드·시설 사진 배치·이용안내를 같은 DB 트랜잭션으로 저장; 공개 상태이면 커밋 후 반영 |
| Trainer + TrainerCareer | 소속·직급·사진 참조·한줄소개·약력을 같은 DB 트랜잭션으로 저장; 프로필과 지점이 모두 공개일 때 반영 |
| Post | 제목·분류·본문·본문 이미지 참조·대표 이미지 참조를 같은 공개 버전으로 제공; 수정 초안은 공개 전까지 별도 유지 |
| Popup | 연결 글·문구·이미지 참조·기간·사용 여부를 함께 저장; 별도 수정 초안 없이 다음 후보 조회에서 판정 |

새 지점·트레이너의 미완성 값은 ‘비공개 준비 상태’로 저장한다. 공개 중인 소개 수정은 저장 즉시 반영되므로 저장 전 수동 검수가 필요하다. 편집 중 기존 공개본을 유지하는 초안·미리보기 기능은 제공하지 않는 안이다. 먼저 비공개로 전환해 편집할 수 있으나 그동안 고객에게도 소개가 보이지 않는다. 본점 비공개는 P-02 제약을 따라야 한다.

부모 저장 실패 시 하위 항목도 롤백한다. 다중 쿼리 공개 조회에서 동시 변경 전후의 관계가 섞이지 않도록 조회 일관성도 검증한다. 업로드 바이너리는 DB 롤백과 같은 단위가 아니다. 부모 저장 실패 후 남은 미참조 파일은 미공개로 남으며 자동 공개·자동 삭제하지 않는다.

Post 수정 초안은 기존 공개 제목·본문·이미지 참조·공개 updated_at·공개일·팝업의 게시글 제목을 바꾸지 않는다. 새 버전을 공개할 때만 반영한다. 최초 공개일 유지 정책은 기존 미확정 제안이다. CMS 최신 리비전을 공개본으로 읽거나 초안 객체를 동적 임베드하여 공개본을 바꾸지 않는다. 다단계 승인·게시글 예약 공개는 추가하지 않는다.

### 2.2 P-02: 최초 준비와 운영 중 본점 보장

목적은 최초 빈 구성을 허용하되 운영 중 고객이 볼 지점·본점이 사라지는 일반 편집을 막는 것이다.

1. 최초 준비는 공개 지점 0개·본점 0개를 허용하고 비공개 준비 지점은 여러 개일 수 있다.
2. 첫 지점 공개와 본점 지정은 원자적으로 수행한다.
3. 공개 지점이 있으면 공개 본점은 정확히 하나다. 비공개 지점을 본점으로 지정하지 않는다.
4. 본점 비공개는 다른 공개 지점으로 본점 변경과 함께 완료해야 한다.
5. 운영 중 마지막 공개 지점의 비공개 전환은 차단한다. 전체 종료·사이트 전체 공개 중단 기능을 추가하지 않는다.

중복 방지와 존재 보장은 서로 다른 검증이다. 첫 공개에서 잠글 기존 공개 행이 없을 때의 동시 요청도 검증한다. PostgreSQL 제약과 직렬화할 잠금 범위를 비교하고, 모든 관리자 저장 경로가 같은 규칙을 적용하게 하는 최소 방식을 선택한다. 구체 잠금·테이블·ORM 구현은 TBD이며 별도 운영 서비스를 도입하지 않는다.

### 2.3 P-03: 삭제 제한·새 자산 교체·복원 검수

목적은 공유 자산 손실과 기존 공개본의 우발적 변경을 막는 것이다.

- 일반 운영자의 지점·트레이너·게시글·팝업·원본 이미지 영구 삭제는 메뉴와 서버 권한 모두에서 차단한다. 비공개/비활성화로 운영하되 사진 배치·약력 한 줄 제거는 부모 편집으로 허용한다.
- 이미지의 시각적 내용을 바꾸면 새 자산을 업로드하고 참조를 바꾼다. 기존 ID·URL의 바이너리를 덮어쓰지 않는다. 캡션·대체 텍스트는 사용 위치에 속한다.
- 공개본·현재 비공개 객체·수정 초안·보존 중 모든 리비전의 이미지 참조를 유지한다. 유지보수 삭제는 이 전체 참조와 본점·소속·팝업 관계를 검사하는 별도 승인 작업이다. 공유 원본은 부모 삭제에 연쇄 삭제하지 않는다.
- 자동 미참조 자산 삭제·자동 리비전 청소·일괄 삭제 화면을 v1에 추가하지 않는다. CMS 참조 인덱스의 리비전 포함 범위는 검증 전까지 보장하지 않는다.
- Post 과거 리비전 복원은 먼저 수정 초안으로 만들고 이미지 존재·관계·공개 가능성을 재검수한 뒤 별도 공개한다. 필수 이미지가 없으면 새 공개를 막고 가짜 경로·임의 사진으로 대체하지 않는다. 실제 파일 유실은 오류 보고·백업 복구 대상으로 다룬다.
- 다른 모델에 신규 범용 복원 기능을 추가하지 않는다. 일반 운영자 권한 제한이 시스템 최고 권한·직접 DB 조작을 불가능하게 만든다는 뜻은 아니다.

### 2.4 P-04: 미공개 원본·썸네일·변환본 보호

목적은 한 번도 공개하지 않은 파일이 URL을 안다는 이유만으로 노출되지 않게 하는 것이다. 공식 Wagtail 문서는 컬렉션 privacy가 문서에 적용되고 이미지에는 적용되지 않는다고 명시한다. 기본 이미지 권한만으로 이 정책을 달성했다고 가정하지 않는다. [Wagtail privacy](https://docs.wagtail.org/en/stable/advanced_topics/privacy.html)

원본은 비공개 저장소 또는 웹 서버가 직접 제공하지 않는 경로에 둔다. 원본·관리자 썸네일·미공개용 변환본은 권한 있는 운영자의 인증된 관리 경로로만 제공한다. 미리보기는 공개 API의 반환 범위를 넓히지 않는다. 무작위 파일명·목록 숨김은 접근 제어가 아니다.

| 이미지 사용처 | 공개 표시본 접근 판정 |
|---|---|
| SiteContent | 유효하게 저장되어 공개 조회되는 설정에서 사용하는 이미지 |
| Branch / BranchPhoto | 현재 공개 지점에서 사용하는 이미지·사진 배치 |
| Trainer | 프로필·소속 지점 모두 공개인 프로필 이미지 |
| Post | 실제 공개본의 대표/본문 이미지; 수정 초안·과거 리비전만의 참조는 제외 |
| Popup | 연결 글 공개 AND 사용 활성 AND 시작 <= 서버 시각 < 종료 |

판정은 공개 조회 규칙을 재사용한다. 브라우저 닫기·오늘 숨김은 이미지 접근 권한이 아니며 서버 후보 판정에 영향을 주지 않는다. 공유 이미지에 공개 사용처가 하나라도 있으면 해당 공개 표시본은 조회 가능하다. 미공개 독점 자료에는 기존 공개 자산 대신 새 자산을 사용한다.

공개 사용처가 모두 사라지면 이후 원본 서버의 무권한 새 조회에서 표시본 제공을 거부한다. 이미 내려받은 파일·외부 및 방문자 캐시의 과거 공개 복사본은 회수 보장하지 않는다. ‘원본 서버’는 파일 전달을 통제하는 서버를 뜻하며 원본 바이너리의 공개를 뜻하지 않는다. 미리보기·보호 이미지 응답은 no-store, 공개 이미지 캐시는 별도 결정하되 장기 공개 CDN 캐시를 자동 도입하지 않는다.

권고 구현 후보는 비공개 저장소와 접근 판정 전달 경로다. 실제 스토리지·내부 파일 전달·서명 URL 방식은 검증 후 선택한다. 서명 URL만으로 철회 후에도 원본 서버가 제공한다면 위 정책을 만족하지 않으므로 매 요청 판정 또는 별도 정책 승인이 필요하다. 이미지 목록 전체의 공개 API는 추가하지 않는다.

## 5. 검증 조건 — 모두 미실행

실행 단계 갱신(2026-09-18): 별도 승인된 SPIKE-01에서 WSL Ubuntu의 Post·CMS 이미지에 한정하여 P-01·03·04를 실험 가설로 검증한다. [실행 보고서](../verification/cms-spike.md)의 SP 결과와 아래 전체 RV 검증 계획은 구분한다. 정책·ADR 상태는 계속 Proposed다.

### 5.1 기존 관리자 안의 최소 연동 기술 검증

새 관리자 프론트를 만들지 않는다. 별도 승인된 기술 검증에서 다음의 가장 작은 연동 범위를 확인한다.

| 대상 | 검증 계층 | 확인할 조건 |
|---|---|---|
| Post 공개 기능 | 관리자·DB·API | 선택 CMS의 리비전/공개 기능으로 Post만 분리 가능한지, 제목·본문·이미지 참조·공개 시각을 함께 읽는지. Wagtail DraftStateMixin은 RevisionMixin과 함께 사용하고 초안 저장과 live 반영을 분리한다. [공식 Snippet 기능](https://docs.wagtail.org/en/stable/topics/snippets/features.html#saving-draft-changes-of-snippets) |
| 부모 편집·현재값 저장 | 관리자·DB·API | 기존 폼/하위 편집을 재사용하여 지점+사진, 프로필+소속+약력을 원자적으로 저장; 일부 오류·동시 요청 시 부분 반영·혼합 조회 없음 |

| 이미지 선택·미리보기 | 관리자·스토리지·브라우저 | 기존 업로드·선택창·썸네일·미리보기에서 인증된 전달이 가능한지; 별도 공개 원본 URL을 생성하지 않는지 |
| 이미지/본문 출력 | API·스토리지·브라우저 | 실제 공개본과 공통 조회에서 허용한 URL만 출력; CMS 전용 태그 제거·안전한 본문 변환·대체 설명 유지 |
| 리비전 참조·복원 | DB·관리자·스토리지 | 현재 객체뿐 아니라 초안·과거 리비전 참조 검사, 복원→수정 초안→검수→공개 순서 및 파일 유실 처리 |
| 전달 우회·캐시 | 스토리지·배포·API | 웹 서버 직접 경로·객체 저장소·원본·썸네일·변환본 접근, 미권한 사용자·로그아웃·공개 철회·팝업 기간 경계, 프록시/서명 URL 재사용 검사 |

CMS 기본 기능만으로 가능한 부분과 작은 확장 훅/저장소·URL 연동이 필요한 부분을 구분해 기록한다. 어떤 방식도 구현 가능·설치 완료라고 미리 판정하지 않는다. 최소 연동으로 정책을 충족하지 못하면 비용과 정책 대안을 다시 검토하며 관리자 전체 재개발로 자동 확대하지 않는다.

## 6. 미결정 사항

운영자/사용자는 §4의 대가를 포함하여 P-01~04를 각각 결정해야 한다. 본 문서 작성 지시는 정책 승인으로 간주하지 않는다. 채택할 CMS·버전, 미디어 저장·전달 방식, 권한 구성, 보존 기간·유지보수 삭제 책임, 리비전 복원 제공 여부는 미정이다. 보호를 낮추는 이미지 즉시 공개 예외는 명시적 승인 없이는 적용하지 않는다.

기존 화면 배치·게시글당 팝업 개수·노출 위치·닫기·오늘 숨김·공개일·API 경로·페이지 크기는 계속 Proposed다. 가격/PT 배제·고객 로그인 배제 등 확정 범위는 유지한다. 기술 검증과 실제 구현은 별도 승인된 작업에서 수행하며 이번 문서 작업 후 자동 시작하지 않는다.
